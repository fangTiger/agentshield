## Purpose

链上风险信号库部署在 BSC 上，用 Agent ID 保证「一个真人一票」，用零知识证明让投票者可以选择匿名，从而记录对域名、地址、Skill 的社区风险信号。信号库提供透明的状态机和申诉机制，合约本身不托管任何资金。

## ADDED Requirements

### Requirement: Agent ID 准入登记
信号库 SHALL 提供登记接口：调用者提交一个身份承诺。登记时，合约 MUST 校验调用者地址在 Agent ID 合约上的 `balanceOf` 大于 0，且每个地址 MUST 只能登记一次。登记成功后，身份承诺加入链上的匿名成员集合，同时触发一个登记事件。

#### Scenario: 持有者登记
- **WHEN** 持有 Agent ID 的地址提交身份承诺
- **THEN** 身份承诺加入成员集合，并触发登记事件

#### Scenario: 非持有者登记
- **WHEN** 未持有 Agent ID 的地址调用登记接口
- **THEN** 交易回滚，返回错误「NotAgentIdHolder」

#### Scenario: 重复登记
- **WHEN** 已经登记过的地址再次调用登记接口
- **THEN** 交易回滚，返回错误「AlreadyJoined」

### Requirement: 身份不可更换
每个地址登记的身份承诺 SHALL 终身不可更换，也不可删除。合约 MUST NOT 提供更换身份的接口。身份秘密丢失后，只能通过本地加密备份恢复；没有备份的地址无法再投票，但不影响本地的扫描和体检功能。

#### Scenario: 不能重新登记新身份
- **WHEN** 已登记的地址试图提交一个新的身份承诺
- **THEN** 交易回滚，返回错误「AlreadyJoined」

### Requirement: 风险对象类型
信号库 SHALL 支持三类风险对象，每个对象由「类型 + 标识」唯一确定：
- **DOMAIN**：规范化后的主机名
- **ADDRESS**：链 ID 加地址
- **SKILL**：Skill 的内容哈希

#### Scenario: 同一对象聚合
- **WHEN** 不同的投票者针对同一个规范化域名投票
- **THEN** 这些投票都聚合到同一个风险对象上

### Requirement: 带证明的投票与按对象隔离的 nullifier
每一票 SHALL 附带一个零知识成员证明。证明的作用域 MUST 绑定链 ID、合约地址和风险对象，证明的消息 MUST 绑定投票类型和证据哈希。投票类型只有两种：「危险」和「误报」。同一个身份对同一个对象 MUST 只能投一票，不论投票交易是由持有者地址发送，还是由中继发送。

#### Scenario: 匿名投票
- **WHEN** 中继提交了一张有效的「危险」票
- **THEN** 该对象的危险票数加 1，事件中不包含任何能识别投票者的信息

#### Scenario: 公开投票
- **WHEN** 持有者地址自己提交了一张有效的「危险」票
- **THEN** 该对象的危险票数加 1，交易发送方就是该持有者地址

#### Scenario: 跨模式重复投票
- **WHEN** 同一个身份已经匿名投过某个对象，又试图用公开模式再投一次
- **THEN** 交易回滚，返回错误「DuplicateVote」

#### Scenario: 他人抢跑提交同一证明
- **WHEN** 第三方截获一份尚未上链的投票证明，并抢先把它提交给信号库或 Semaphore 合约
- **THEN** 这一票仍然只会被计入一次，计入的投票内容与原投票者一致，原投票者的投票不会被「烧掉」

#### Scenario: 无效证明
- **WHEN** 提交的证明校验失败，或者使用的根不在允许的历史根范围内
- **THEN** 交易回滚

### Requirement: 只能标记危险
信号库 MUST NOT 提供把对象标记为「安全」的投票类型。「误报」票只能用来对抗危险信号，不会产生「安全」状态。

#### Scenario: 不存在安全状态
- **WHEN** 某个对象的误报票数远高于危险票数
- **THEN** 该对象的状态为「有争议」或「待验证」，而不是「安全」

### Requirement: 信号状态机
每个对象的状态 SHALL 根据链上票数和时间推导得出：
- **待验证**：至少有 1 张危险票，但还没达到确认条件
- **社区确认**：危险票数不少于 N，从第一张危险票算起已过冷静期 T，并且危险票数不少于误报票数的 2 倍
- **有争议**：误报票数不少于 N，且误报票数不少于危险票数

N 和 T SHALL 在部署时设定、公开披露，并且不可修改。

#### Scenario: 达到确认条件
- **WHEN** 某个对象获得 N 张危险票，已过冷静期 T，且没有误报票
- **THEN** 查询该对象，状态为「社区确认」

#### Scenario: 冷静期未满
- **WHEN** 某个对象在冷静期内获得了 N 张危险票
- **THEN** 状态仍为「待验证」

### Requirement: 申诉
任何地址 SHALL 都可以针对某个对象提交申诉记录（附证据 URI）。申诉只会被记录并展示，不会删除或修改任何票数。申诉是否成立，通过社区的误报票来体现。

#### Scenario: 项目方申诉
- **WHEN** 被标记的域名的所有者提交了一条申诉
- **THEN** 链上留下申诉事件，网页在该对象下展示申诉内容

### Requirement: 种子信号
信号库 SHALL 支持由公开披露的种子地址写入种子信号，用来导入公开情报。种子信号 MUST 单独计数并标注来源，MUST NOT 计入社区票数，也 MUST NOT 单独让对象进入「社区确认」状态。种子地址 MUST NOT 能删除或修改社区票数。

#### Scenario: 只有种子信号
- **WHEN** 某个域名只有种子信号，没有任何社区票
- **THEN** 查询结果显示「情报源标记」，社区状态为空

### Requirement: 无资金托管与权限披露
信号库合约 MUST NOT 持有或转移任何用户资产，MUST NOT 提供可升级代理或暂停功能。所有特权角色（只有种子地址一种）及其权限 SHALL 在合约源码和项目文档中完整披露。合约 SHALL 在 BscScan 上验证开源。

#### Scenario: 拒绝接收资产
- **WHEN** 有人直接向信号库合约转入 BNB
- **THEN** 交易回滚

### Requirement: 匿名中继
系统 SHALL 提供匿名中继服务：接收证明和投票内容，先在链下校验证明有效，再代付 gas 提交上链。中继 MUST NOT 要求任何身份信息，MUST 有限流措施，并且 MUST NOT 记录请求方的 IP 与投票内容之间的对应关系。

#### Scenario: 中继拒绝无效证明
- **WHEN** 中继收到的证明在链下校验失败
- **THEN** 中继拒绝请求，不发送交易

#### Scenario: 中继提交成功
- **WHEN** 中继收到有效的证明
- **THEN** 中继提交交易，并返回交易哈希

### Requirement: 查询接口
信号库 SHALL 支持按对象查询以下数据：危险票数、误报票数、种子信号、首票时间、申诉数量、推导出的状态。同时 SHALL 支持查询全局的登记人数。

#### Scenario: 查询对象
- **WHEN** Skill 查询某个 Skill 内容哈希
- **THEN** 返回该对象的各项计数和当前状态
