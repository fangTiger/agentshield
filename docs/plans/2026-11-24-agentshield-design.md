> 日期：2026-11-24 ｜ 状态：待用户评审

## 1. 定位

**AgentShield：Agentic Wallet 的授权与信任守卫。**
在扫码、确认配对码、安装 Skill 之前，先问它一句。每条风险信号都由持有 Agent ID 的真人确认，一个人只有一票。确认可以匿名，被标记的一方也可以申诉。

Agent ID 在这里不可替代：正因为一个 KYC 只能对应一个 Agent ID，而且不能转让，「每一票来自不同的真人」才成立；再加上零知识证明，投票者就能做到「匿名，但仍然一人一票」。

能力边界要说清楚：我们做的是**体检**，不是**拦截**。App 里的扫码和确认流程，Skill 看不到。「群体免疫」只是愿景，不是已经实现的能力。

## 2. 选题过程（为什么是它）

| 方向 | 结论 | 原因 |
|---|---|---|
| Agent 斗兽场（博弈游戏） | 否决 | 实用性弱，玩法也不够新 |
| AgentJury（AI 陪审团） | 否决 | 冷启动太难 |
| Agent 红包 | 否决 | 创意不足 |
| AgentZK + AgentShield（加入扫码授权安全） | **采纳** | 实用：安全正是评委最在意的；技术上有亮点：ZK；没有冷启动问题：种子数据由我们自己提供 |

## 3. 人工与自动的分工

**只有加入这一步需要人工操作并动用钱包，之后全部自动完成。**

| 环节 | 执行方 | 频率 |
|---|---|---|
| 在币安 App 领取 Agent ID | 👤 人工 | 一次 |
| 在 App 内开启开发者模式（Agent 无法代为开启） | 👤 人工 | 一次 |
| 安装 AgentShield Skill | 👤 人工，说一句话即可 | 一次 |
| 加入网络：在本地生成身份，然后调用 `join` 上链 | 🤖 自动，用户在对话中确认一句 | **一次，这一步就是计入「30 个地址」的交互** |
| Agent 安装任何 Skill 之前，自动跑红线扫描 | 🤖 全自动 | 每次安装 |
| 遇到授权、配对码相关的内容时，自动做体检 | 🤖 全自动 | 随时 |
| 发现高风险时，生成 ZK 证明，经中继匿名上报 | 🤖 全自动，默认开启，可以关闭 | 随时 |
| 用户转发二维码问「这个能扫吗」 | 👤 人工发起，🤖 自动分析 | 偶尔 |
| 用自己的地址公开确认某个风险 | 👤 人工发起，需要确认 | 可选 |

匿名上报不需要动钱包，不需要开发者模式，也不消耗用户的 gas，由中继代付。

所谓「社区确认」，就是许多 Agent 各自独立扫描之后自动形成的共识。扫到同一个风险的 Agent 越多，信号越强。

## 4. 风险数据从哪里来

### 4.1 冷启动种子：我们自己提供，第一个用户当天就能受到保护

| 用途 | 数据源 | 规模、许可证与用法 |
|---|---|---|
| 钓鱼域名、恶意地址 | **ScamSniffer scam-database**（GitHub，每天更新） | domains.json 约 9 MB，address.json 约 12 万字节；GPL-3.0，**只在运行时拉取，不复制到我们的仓库** |
| 钓鱼域名 | **MetaMask eth-phishing-detect** | config.json 约 3.5 MB，包含黑名单、模糊匹配名单和白名单；许可证待确认 |
| 钓鱼网站、地址风险的实时查询 | **GoPlus Security API** | `phishing_site`、`address_security`（chain_id=56）。已实测可以免费调用 |
| 官方域名白名单 | 币安官方公告和文档 | 人工维护并写死在 Skill 中，每一项都附有依据链接 |
| 恶意 Skill 样本 | **主动扫描 ClawHub 上的公开 Skill**（MIT，约 9.5k star 的注册表） | 我们用红线扫描器批量扫描，高风险结果作为种子写上链。**这一部分是我们自己产出的独有数据** |
| 良性基线（衡量误报） | **binance-skills-hub**（币安官方） | 官方 Skill 应该零命中，用来校准误报率 |
| 恶意 Skill 的 IOC | 公开安全报告（ClawHavoc 事件，2,857 个 Skill 中有 341 个是恶意的；Unit 42 关于 OpenClaw 供应链风险的报告） | 整理出其中的域名和地址，作为种子 |
| Skill 扫描规则参考 | snyk/agent-scan（Apache-2.0）、cisco skill-scanner | 参考它们的规则思路；我们的特色是对照币安的 6 条红线 |
| 话术和注入检测的评测集 | deepset/prompt-injections、Lakera/gandalf_ignore_instructions、jackhhao/jailbreak-classification，以及自建的 Agentic Wallet 钓鱼话术样本 | 用来测检出率和误报率，结果公开 |

### 4.2 持续增长的数据：来自社区，自动产生
- 每个 Agent 在扫描或体检中发现高风险时，自动匿名上报。
- 用户可以主动公开确认，也可以对误报投「误报」票。
- 项目方可以对被标记的内容提交申诉。

### 4.3 两条原则
- **链上只写高相关的数据**：只写与币安、Agentic Wallet、Agent ID 有关的仿冒域名，以及恶意 Skill 的哈希。完整的大名单只在用户本地使用，以控制链上成本，并保证数据有意义。
- **每条数据都标注来源**：种子数据和社区信号分开计数，种子数据不能单独让一个对象进入「社区确认」状态。

## 5. 增长：凑满 30 个真实的 Agent ID 地址

1. **其他参赛者**：他们都持有 Agent ID，而且都在写 Skill。他们需要证明自己的 Skill 不违反红线，可以用 AgentShield 来扫描并出具说明。
2. **安全科普传播**：在 X 上发「扫码钓鱼防范指南」，带上 #BinanceWalletHackathon 和 #AgenticWallet，同时冲社区传播奖；也发到币安广场和中文 TG 群。
3. **身边的真实用户**：每个人都用自己的 KYC 领取、自己操作。**严禁**批量注册账号或代人操作。
4. **兜底**：生态领航奖没有 30 个地址的门槛，即使创新奖没拿到参评资格，产品仍然可以参与评奖。

## 6. 三分钟演示

1. **授权体检**：收到一个仿冒的「Agent ID 空投验证」二维码，Agent 解码后标出可疑的域名和诱导输入配对码的原文，并用一句话解释后果：「确认之后，另一个 Agent 就能操作你的钱包。」
2. **红线扫描**：安装一个藏有「交易无需确认」指令的恶意 Skill，扫描器高亮红线第 2 条。用户确认后公开上链，在 BscScan 上展示这笔交易。
3. **共享信号**：第二个 Agent 安装同一个哈希的 Skill，立即看到「N 位真人确认」的风险信号。
4. **匿名投票**：交易的发送方是中继，看不出投票人是谁；同一个人用同一个 nullifier 再投一次，交易被回滚，证明「匿名，但一人一票」。
