# AgentShield 三方共识（Claude 主持人 × Claude 子 Agent × Codex）

> 经过两轮讨论，于 2026-11-24 达成共识。原始讨论记录见同一目录下的 00 至 02 号文件。

## 定位
**AgentShield：Agentic Wallet 的授权与信任守卫。**
扫码前、确认配对码前、安装 Skill 前，先问它。每条风险信号都由持有 Agent ID 的真人确认，一人一票，可以匿名，也可以申诉。
「群体免疫」只作为愿景出现，不作为已实现的能力对外宣称。

## 两大支柱（共用一个风险引擎和一个链上信号库）
1. **授权体检（主打，demo 第一幕）**
   - 只分析用户交给 Agent 的内容：链接、二维码、话术。
   - 检查项：
     - 严格匹配官方域名、协议和路径，防范同形字、子域名、跳转等伪装；
     - 识别是否为 Agentic Wallet 授权请求；
     - 识别诱导输入配对码的话术；
     - 对照本机 `baw` 的登录记录，作为辅助信号。
   - 官方格式还没核实的部分，一律显示为「未知」，不判定为安全。
   - **不宣称「拦截」**：App 内的扫码和确认流程对 Skill 不可见。产品要做的是用大白话说清楚「确认之后，另一个 Agent 就能操作你的钱包」。
2. **Skill 红线扫描**
   - 安装第三方 Skill 前，逐条对照官方 6 条安全红线进行扫描。
   - 先跑静态规则，再让 LLM 审查；LLM 只能把风险往高调，不能往低调。
   - 扫描结果以 Skill 内容哈希为键，写入链上。
   - 展示时说明：安装 Skill 等于授予它操作权限，但这与钱包登录授权不是同一件事。

**执行防线：砍掉**，不重复 GoPlus 和 baw preview 已有的检测。

## 链上信号库与 Agent ID 的作用
- **登记**：持有者地址调用 `join(commitment)`，合约校验 `balanceOf(msg.sender) > 0`，每个地址只能登记一次。身份秘密由 Agent 在本地生成，并加密备份。登记、换绑、丢失后的恢复规则必须写清楚。
- **投票只有一条路径**：每一票都附带 Semaphore v4 证明和按议题隔离的 nullifier。
  - 持有者地址自己发送交易，就是**公开模式**，计入链上指标，需要自付 gas。
  - 中继代为发送交易，就是**匿名模式**。
  - 两种模式共享 nullifier，同一个身份对同一个议题只能投一票。
- **基础设施**：使用 Semaphore v4 官方合约，链上 LeanIMT 增量树，并保留有限的历史根。证明绑定链 ID、合约、议题、动作和内容哈希，在 Agent 本地用 snarkjs 生成。
- **信号规则**：
  - 只能标「危险」，不能标「安全」；官方域名白名单写死在 Skill 里。
  - 状态默认是「待验证」，需要达到 N 个不同的真人确认并经过冷静期后，才变为「社区确认」。
  - 提供申诉、撤回、更正的通道，保留版本记录。
  - 种子数据和社区报告分开标注来源。
  - 措辞统一用「社区信号」，不下「诈骗」的定性。
- **首版不做**：个人信誉、名字排行榜、浏览器插件。网页只显示「N 个真人确认」，不展示 handle 对应的地址，以免违反「按名字查钱包」这条红线。

## 安全约束（针对我们自己）
- 举报内容、网页内容、被扫描的 Skill 文本，一律视为不可信数据，不进入 LLM 的指令区，也不能触发任何工具调用。
- 我们只使用官方 `baw` 流程：不做扫码登录，不接触会话，不接触配对码，不接触任何密钥。
- 合约开源，owner 权限全部披露，尽量把权限交给多签，或者干脆不设 owner。
- 开启开发者模式时，要如实说明用途，并建议用户把开发者模式的额度设到最低。

## 第 0 号任务（实现前必须完成的实测）
1. 用 `baw` 真实发起一次登录，抓取授权链接或二维码的格式。
2. 在 BSC 主网实测 gas：分别测量证明验证、树插入、calldata，以及整笔交易的成本。参考基准是 validateProof 约 28.6 万 gas。
3. 测试 App 地址簿能否添加合约地址，以及能否通过转账触发 `receive()`。这只是实验性的备选入口，不作为主路径依赖。
4. 向赛方确认：登记交易和投票交易，是否计入「30 个 Agent ID 地址交互」的统计口径。
5. 在第一个版本上线时，提前招募 30 个真实持有者进行实测。

## Demo（3 分钟）
1. 收到一个仿冒的「Agent ID 空投验证」二维码或话术，Agent 做授权体检：标出可疑域名和诱导输入配对码的原文，并解释风险。
2. 演示安装一个藏有「交易无需确认」指令的恶意 Skill，扫描器高亮红线第 2 条。用户确认后，结果上链，打开 BscScan 展示这笔交易。
3. 第二个 Agent 安装同一个 Skill（内容哈希相同），立即看到「N 个真人确认的风险信号」。
4. 匿名举报：交易发送方是中继；用同一个 nullifier 再投一次，交易被 revert。
