# 第 2 轮：主持人立场

**D1 主打功能**：用「授权」这个概念统一叙事。
- 安装 Skill 是授权它操作你的钱包，扫码登录也是授权，两者本质相同。产品定位为「Agentic Wallet 授权守卫」，这样既满足用户要求的「扫码授权安全」，又能拿最容易落地的 Skill 扫描做最硬核的演示。
- 浏览器插件：首版不做。等实测拿到授权链接格式后，再决定是否加进来。

**D2 ZK 与信誉**：放弃「共享 nullifier」的方案，改为**两类信号分开计数、分开展示**：
- 公开背书和投票：持有者地址直接发交易，按地址去重（一个 Agent ID 对应一个地址），信誉记到 `name.ai` 上
- 匿名举报：ZK 证明加中继提交，按 nullifier 去重
- 界面上把「公开确认 N」和「匿名举报 M」分开显示，**不加总**。这样就不存在一个人用两种模式重复计票的问题，复杂度也明显降低。

**D3**：思路值得验证，但不能依赖。
- `receive()` 收不到 calldata，所以通过转账只能完成「加入守护网络」这种无参数的动作。
- 合约收到转账后应在 `receive()` 里立即原路退回，不截留任何资金。
- 实现阶段的第 0 号任务：实测 App 地址簿能否添加合约地址，以及最小转账金额是多少。

**D4**：接受「初步估算约 30 万 gas + 实现阶段在主网实测」的说法。

**D5**：「群体免疫」只作为愿景来讲，不作为能力宣称。对外的一句话定位是：
**「装 Skill、扫码、确认配对码之前，先问一下 AgentShield。这是一个由 Agent ID 真人背书的 Agentic Wallet 授权安全层。」**
