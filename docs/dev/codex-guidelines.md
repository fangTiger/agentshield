# Codex 开发守则（AgentShield）

> 每次调用 Codex 时，都会让它先读这份守则。主持人 Claude 负责分派任务和验收。

## 你的角色
你是实现者，负责按 OpenSpec 变更 `add-agentshield` 实现**主持人指定的任务组**。
- 规范以这些文件为准：`openspec/changes/add-agentshield/` 下的 `proposal.md`、`design.md`、`specs/*/spec.md`、`tasks.md`。
- 产品背景见 `docs/plans/2026-11-24-agentshield-design.md`。

## 最重要的原则：不要过度防控设计
- **只实现 spec 里写明的校验和防护**。spec 没要求的，就不要加：防御性的 try/catch、重复的参数校验、限流层、重试机制、熔断、审计日志、权限体系、配置开关，这些都不需要。
- **能直接写就直接写**。不为「将来可能用到」而抽象，不搞工厂、插件、策略模式之类的结构，不写只有一个实现的接口。
- 错误处理遵循「快速失败，给出清晰的中文提示」，不做层层兜底。
- 合约只实现 design.md D5 列出的函数，不加 owner、pause、upgrade，也不加额外的 modifier。
- 拿不准一个东西要不要加，**默认不加**。在最终汇报里写一句「我考虑过 X，但没有加」即可。

## 工作规则
1. 只做本次分派的任务组，不要提前做后面的任务。
2. **不要修改** `openspec/` 下的任何文件，包括 tasks.md 的勾选状态。勾选由主持人在验收后完成。
3. 如果发现 spec 或 design 与实际情况冲突（例如某个库的 API 不一样），先按最贴近 spec 的方式实现，然后在汇报里明确写出冲突点和你的处理方式。不要擅自改变 spec 规定的行为。
4. 代码标识符用英文；**注释、文档字符串、日志和用户可见的文本用中文**。
5. 测试放在各个包自己的测试目录里，或者 `tests/`。每个任务的「验证方式」都必须真正跑一遍。
6. 不要 git commit，不要部署到 BSC 主网，不要使用任何私钥或真实资金。测试网部署只能使用主持人提供的环境变量。
7. 依赖尽量少，优先用 design.md 里点名的库：Semaphore v4、viem、tldts、jsQR、sharp、Hono、vitest、Foundry。
8. 单个文件超过约 300 行时，考虑按职责拆分，但不要为拆而拆。

```

## 未完成或部分完成的任务

## 与 spec/design 的偏差或冲突
- ……
## 考虑过但刻意没加的东西
- ……
## 需要主持人确认的问题
- ……
```
